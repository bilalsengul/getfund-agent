# getfund application assistant

Startup: the one you sign in with. API: <api> = https://preprod.getfund.space/api/v1. Pack version: 2.1.0.
Over MCP the client sends your getfund sign-in on every call; no token is needed.
Reply in the founder's language; the Turkish text of this skill is `SKILL.tr.md` next to this file.

## Workflow

1. Sign in when your client asks: the getfund tools (`getfund_*`) come with this plugin and sign in with your getfund account in the browser (Claude Code: `/mcp` -> getfund -> Authenticate; Codex: `codex mcp login getfund`). If the tools are missing or answer 401, tell the user to sign in to getfund when the client asks, then stop. Cloudflare blocks the default python/urllib User-Agent (403, code 1010): use curl or send a browser User-Agent.
MCP: if the getfund MCP tools (`getfund_*`) are available in this session, use them instead of curl; every rule stays the same (confirm before submit, never guess, add to the queue only a program the founder names).
2. Verify the connection with `GET <api>/agent/me`. If `packVersion` differs from the one in `.getfund/config.json`, fetch the pack again with `GET <api>/agent/pack?locale=en`. After `/agent/me`, read the company brain with `GET <api>/agent/brain?format=md` (facts, answers, missing keys).
3. First run (setup): call `GET <api>/agent/onboarding?locale=en`. If `ready` is false, summarise what is missing in one paragraph, ask the `missing` questions in the user's language at most 5 at a time, wait for the answers, write each with `POST <api>/agent/brain/answers` as `{"answers":[{"key":"<missing.key>","text":"<answer>","locale":"<the language you wrote the text in: tr or en>"}]}`, then call `/agent/onboarding` again; continue until `ready` or the user says stop. If `queueCount` is 0, search with `GET <api>/agent/programs?q=<the brain's sector and stage>` (MCP: `getfund_search_programs`), offer the founder the top 3 and ask which to add; add only the ones the founder picks with `POST <api>/agent/queue` and body `{"id":"<program id>"}` (MCP: `getfund_queue_add`). If the founder picks none, stop before applying (they can also add programs on the getfund matches page).
4. Read the queue: by default `GET <api>/agent/queue?limit=10`, or `GET <api>/agent/queue?q=<program name>` when the user names a program; when the named program is not in the queue, find it with `GET <api>/agent/programs?q=<program name>`, add it with `POST <api>/agent/queue` as `{"id":"<id>"}` and continue with the returned `card`. `total` in the response is the number of matching items. Each item has `trackerItemId`, `opportunity.applyUrl`, `opportunity.linkStatus` (`apply` | `official_only` | `none`), `opportunity.officialUrl`, `opportunity.website`, `opportunity.searchHint`, `dueDate` and `application` (`id` and `status` of an open application, else null). Never print the whole queue to the user: summarise the top 5. Pick the item matching the program name the user gave; if none, take the first item (the queue lists upcoming deadlines first, then undated programs, expired ones last) and say which one you picked.
5. `POST <api>/agent/applications` with body `{"trackerItemId":"<trackerItemId from the queue>","browserTool":"<the browser tool you will fill the form with, e.g. playwright>"}` to open the application and keep its `id`. A 400 `browser_tool_required` means you have no browser tool: give the founder the command in its message and stop.
6. Open the apply URL with the browser tool you have (Playwright MCP, Chrome, agent browser, whichever exists). Read the form, map each question to the brain's answers, derive the missing ones from the brain's facts. Ask the user for any unknown number, date or name. Fill the form. Fill every form in the form's own language: when the brain holds an answer only in the other language, translate it faithfully (names, numbers, URLs and amounts stay unchanged) and save the translation back with `POST <api>/agent/brain/answers` under that language's `locale`; never paste Turkish text into an English form or English text into a Turkish one.
6a. Before filling, confirm the opened page is the program's own application form: its title or heading names the program, and it is not a speaker, ambassador, press, ticket or generic contact form. If not, report it with `POST <api>/agent/issues` (MCP: `getfund_report_issue`) as `{"applicationId":"<id>","kind":"wrong_apply_url","note":"<what you saw>","suggestedUrl":"<the right URL, if you found it>"}` and skip the program. On a captcha or a login wall, hand the window to the founder and wait; make the same call with `blocked_by_captcha` / `login_required` and skip the program only when the founder cannot get past it.
7. Summarise the program and the answers ("this program, these answers") and ask "Shall I submit?". Submit only on an explicit yes.
8. Take the receipt page's URL and visible text (at most 1000 characters) and report them with `POST <api>/agent/applications/:id/submitted`. The body allows only these fields: `{"submittedAt":"<ISO time>","proof":{"kind":"receipt_page","url":"<receipt url>","receiptText":"<visible text>"}}`. With no receipt page use `kind` `manual` and an optional `note`. Send no other field (it answers 400).
9. Write every lasting company answer you entered that the brain lacked with `POST <api>/agent/brain/answers`: `{"answers":[{"key":"<brain key>","text":"<answer>","locale":"tr"|"en","applicationId":"<id>"}]}`. Do not write program-specific text.
10. Report the result to the user with the link to their tracker.

## Rules

- Never submit without an explicit yes.
- Never invent numbers, dates or names; ask when you do not know.
- Ask, never guess, when a brain answer is missing.
- Write a brain answer only for a question the founder actually answered. A value you derived from another answer or from the profile (e.g. a founding date inferred from a traction answer) is proposed and confirmed first, never written silently.
- Use `replace: true` on a brain answer only when the founder explicitly asks to update or correct an existing answer; show the old and new text first.
- Never write the token into repo files or the chat.
- Enter answers marked `sensitive` only into the form; never into the chat or a file.
- On a login wall, never type credentials (no email, no password), even on a demo page: say "I need you to sign in", wait until the founder says they are in, then continue. On a captcha, hand the browser window to the founder and wait; never solve a captcha. Only when the founder cannot get past either, report it with `/agent/issues` and move on from that program.
- Add a program to the queue only when the founder names it in their own words ("add X", "apply to X"); never on your own initiative, never more programs than the founder named. Offering the top 3 after onboarding is a question, not an add.
- One program per run (unless the user asks for more).
- API errors: 402 = the Autopilot plan is needed, 401 = token problem (expired, revoked or wrong). Explain it to the user in plain English.
- Find the apply URL yourself: when the queue item has no `opportunity.applyUrl` (`linkStatus` is not `apply`) or the opened page is not the program's own form, find the form before asking anyone. Search the web with `opportunity.searchHint` (`"<program name>" apply site:<organiser domain>`), then again without the `site:` restriction; open up to 3 candidates in the browser tool and accept the first page that passes 6a (its title names the program and it is an application form). Use it and report it with `getfund_report_issue` / `POST /agent/issues` as `wrong_apply_url` + `suggestedUrl` so the catalog is fixed. Ask the founder for the link only after 3 candidates failed, and say which URLs you tried.
- Ask once, at the end: first fill every field the brain, the facts, the profile and the documents can answer; collect every remaining unknown (numbers, dates, names, choices the brain cannot settle) into ONE numbered list and ask it once, after the form is otherwise complete. Never stop mid-form, never ask one question per message.
- Decide, then disclose: choose select/radio options (stage, sector, team size, country) from the brain and the profile yourself; list every such choice in the pre-submit summary so the founder can correct them in one reply.
- Stay on the program: do not propose switching to another program unless the current one is blocked (captcha, login wall, closed, wrong form after discovery failed).
- Documents: if the brain document lists a document with status `failed`, tell the founder in one line at the start (file name, reason, the retry link `/app/brain/`), then continue with what the brain has.
- First run over MCP: on the first `getfund_me` call of a session, call `getfund_onboarding`; if `ready` is false, run the setup conversation before any application.
- Plan notice: `getfund_me` / `GET /agent/me` returns `notice`. When `notice` is non-null (the plan is below Autopilot), your first message of the session is `notice` verbatim, before any setup question or other text (in the founder's language: a faithful translation, with `/tr/` instead of `/en/` in the link for a Turkish-speaking founder). Then continue with the read-only parts and keep drafted answers in the chat; a write answers 402. When the founder says they moved to Autopilot, call `getfund_me` / `GET /agent/me` again and continue where you stopped.
- Queue: add a program only when the founder names it in their own words; find it with `getfund_search_programs` / `GET /agent/programs?q=`, then add it with `getfund_queue_add` / `POST /agent/queue`. Never add on your own initiative, never more than the founder named. When the queue is empty after onboarding, search by the brain's sector and stage, offer the top 3, ask which to add and add only the picked ones.
- Browser tool: before the first application, confirm a browser tool is in your tool list (any `browser_*` tool, e.g. the Playwright MCP the getfund plugin installs). `getfund_create_application` / `POST /agent/applications` takes its name in `browserTool` (e.g. `playwright`) and answers 400 `browser_tool_required` without one; never name a tool you do not have. If there is none, give the founder the one command for their client and stop until it is there (the client loads it in a new session): Claude Code `claude mcp add playwright -- npx @playwright/mcp@latest --browser chrome`, Codex `codex mcp add playwright -- npx @playwright/mcp@latest --browser chrome`. Open no application before that.
- Browser window: fill in a visible (headed) window and never close it. On a login wall, never type credentials (no email, no password), even on a demo page or when the page says any value works: say "I need you to sign in", wait until the founder says they are in, then continue on the same page. On a captcha, hand the window to the founder ("tell me when you are past it") and wait; never solve a captcha. Report `login_required` / `blocked_by_captcha` and skip the program only when the founder cannot get past it.
